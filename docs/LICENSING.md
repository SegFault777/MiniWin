# Licensing

## The project: GPL-3.0-only

From **MiniWin 1.1-alpha-1** the project is licensed under the **GNU General Public License, version 3**
(SPDX identifier `GPL-3.0-only`). The complete text is in [`LICENSE`](../LICENSE). Every hand-written source file
(`kernel/`, `boot/`, `tools/`, `build.sh`, the test programs) starts with the line

    SPDX-License-Identifier: GPL-3.0-only

in the comment syntax of its language, so the license of a single file can be read, and checked by tools, without
opening the top-level notice. "Only" is deliberate: it is the literal "GPL 3.0". To allow later versions of the GPL as well,
change `GPL-3.0-only` to `GPL-3.0-or-later` in the README notice and in the files (one `sed`), and say so in the commit.

What the GPL asks of someone who distributes MiniWin, or a program built from it, in short: pass on the same freedoms
(the source, under the same license), keep the notices, and do not add further restrictions. It places no restriction
on *running* MiniWin or on the documents you create with it. This paragraph is a summary, not the license; the license
text governs.

## What is **not** under the project license

Third-party material keeps its authors' license. Nothing in `third_party/` was relicensed.

| Dalmoori font | `third_party/dalmoori-font/` | Apache-2.0 |

Not GPL: art and code are separate works. See `third_party/icon-bundle/NOTICE.md` |

The generated data files (the two font headers, `trusted_roots.h`, `ecc_tests.h`) carry no SPDX line on purpose: they
are outputs of third-party data, so labelling them GPL would be wrong. Each is regenerated by a script in `tools/`
(see the scripts' headers) and its notice lives in the matching `third_party/*/NOTICE.md`. The other generated file,
`kernel/chain_mbr.h`, is produced from this project's own `boot/chain_mbr.asm` and is labelled GPL-3.0-only (the generator
`tools/gen_chain_mbr.py` writes the line).

Compatibility notes. Apache-2.0 code may be combined into a GPLv3 work (the reverse is not true), so bundling
Dalmoori is fine. The OFL font is bundled as data embedded in the kernel image; the OFL's own terms (keep the notice
and license, do not sell the font by itself) continue to apply to those font files, which is why they stay under their
own notice.

### The icons: CC BY-SA 4.0

From **1.1-alpha-6** the icon pack is licensed CC BY-SA 4.0 instead of GPL-3.0-only (its author's choice; before that it was
covered by the project license). Three practical points. First, a disk image (`os-image.img`) contains both: the GPL-3.0-only
kernel and the CC BY-SA 4.0 icon catalog, distributed together as a collection -- whoever redistributes an image must satisfy
both licenses for their respective parts (source and notices for the code; credit and share-alike for the icons). Second,
the five mouse cursors are the one part of the pack compiled into the kernel image (`kernel/cursor_data.h`, generated by
`tools/gen_cursors.py`, labelled `CC-BY-SA-4.0`): the image carries those bitmaps under CC BY-SA 4.0 next to GPL code. Third,
changing a pack icon and shipping it means shipping that change under CC BY-SA 4.0 too. CC BY-SA 4.0 is one of the licenses the
FSF and Creative Commons recognise as compatible in one direction with GPLv3 (BY-SA 4.0 material may be adapted into a GPLv3
work), but the pack is data kept separate from the code, so this project does not rely on that. The MiniWin logo
(`docs/logo/`) is project artwork supplied by its author; no separate license has been stated for it yet.

## Adding a new file

Put `SPDX-License-Identifier: GPL-3.0-only` on the first line (after a `#!` line if there is one) of every new source file you
write, in the comment style of the language (`/* ... */` for C and linker scripts, `;` for NASM, `#` for shell and
Python). A file that is *generated from third-party data* does not get the line; add its notice to
`third_party/<name>/NOTICE.md` instead.
